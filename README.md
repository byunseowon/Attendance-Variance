# 수료보고 출석률 비교 프로그램

백오피스(내부 관리 시스템)와 HRD-Net 출석부의 출석률을 수강생 단위로 비교하여,  
수료보고 전 불일치 항목을 신속하게 확인하기 위한 단일 HTML 도구입니다.

---

## 배경

수료보고 시 백오피스 출석률과 HRD-Net 출석부 출석률이 일치하지 않으면 보고가 반려될 수 있습니다.  
두 시스템을 수동으로 대조하는 작업은 인원이 많을수록 오류가 발생하기 쉬우며 시간이 많이 소요됩니다.  
이 도구는 두 데이터를 한 화면에서 자동 비교하여 즉시 확인이 필요한 항목만 추려냅니다.

### 도입 효과

| 구분 | 기존 방식 | 이 도구 사용 시 |
| --- | ---: | ---: |
| 수료보고 대조 소요 시간 | **1~2시간** | **5분 이내** |
| 방식 | 수강생 1인씩 두 시스템 수동 비교 | 붙여넣기 + 파일 업로드 후 자동 판정 |
| 오류 위험 | 높음 (피로·누락 발생) | 낮음 (전수 자동 비교) |

---

## 주요 기능

| 기능 | 설명 |
| --- | --- |
| **자동 매칭** | 이름 + 주민번호 앞 6자리 기준으로 백오피스-HRD 수강생을 자동 매칭 |
| **출석률 차이 판정** | 설정한 허용 임계값을 기준으로 OK / 주의 / 오류 자동 판정 |
| **미매칭 인원 감지** | 한쪽 시스템에만 존재하는 수강생을 상단에 즉시 표시 |
| **인원 현황 비교** | 수료생 / 조기수료 / 중도하차 구분별 인원 일치 여부 확인 |
| **예상 사유 입력** | 주의·오류·미매칭 항목별로 사유를 직접 메모 가능 |
| **슬랙 전달용 정리** | 체크한 항목만 슬랙에 전달하기 좋은 텍스트 형식으로 자동 생성 |
| **CSV 내보내기** | 비교 결과 전체를 날짜 포함 파일명으로 저장 |
| **표 복사 (TSV)** | Google Sheets 붙여넣기 최적화 형식으로 클립보드 복사 |
| **필터** | 전체 보기 / 주의·오류만 보기 전환 |

## 사용 방법

### 1단계 — 트랙과 기수 선택

Redash에서 실제 시작한 트랙 목록을 자동으로 불러옵니다. 트랙을 선택하면 해당 트랙의 과거 및 현재 기수만 표시되며, 기수를 선택하면 수강생 출결 데이터가 자동으로 조회됩니다.

- 미래 시작 기수는 선택 목록에서 제외합니다.
- 수강생 데이터는 `dblms_trainees`와 `dblms_trainee_attendance_summaries`에서 조회합니다.
- 일반 수료와 조기수료는 `statuslogs`의 최근 사유를 기준으로 구분합니다.

### 2단계 — HRD 출석부 엑셀 업로드

HRD-Net에서 내보낸 출석부 파일(`.xlsx` 또는 `.xls`)을 업로드합니다.

- 파일 클릭 선택 또는 드래그 앤 드롭 모두 지원합니다.
- 파싱 대상 항목: 성명, 주민등록번호, 훈련생 상태, 훈련일수, 출석일수, 출석률 일(%)

### 3단계 — 허용 가능한 차이 설정

두 가지 임계값을 각각 설정합니다. 기본값은 각 5%p입니다.

| 항목 | 설명 |
| --- | --- |
| **HRD 높을 때** | HRD 출석률이 백오피스보다 이 값을 초과하면 **주의(노란색)** |
| **HRD 낮을 때** | HRD 출석률이 백오피스보다 이 값을 초과로 낮으면 **오류(빨간색)** |

### 4단계 — 비교 시작

`비교 시작` 버튼을 클릭하면 결과가 즉시 화면에 표시됩니다.

---

## 판정 기준

| 판정 | 배경색 | 조건 |
| --- | --- | ---: |
| **OK** | 흰색 | 차이가 허용 범위 이내 |
| **주의** | 노란색 | HRD 출석률이 백오피스보다 설정값 초과로 높음 |
| **오류** | 빨간색 | HRD 출석률이 백오피스보다 설정값 초과로 낮음 |
| **HRD 없음** | 빨간색 | 백오피스에는 있으나 HRD에 없음 |
| **백오피스 없음** | 빨간색 | HRD에는 있으나 백오피스에 없음 |
| **조기수료** | 회색 | 조기수료 처리된 수강생 |
| **중도하차** | 회색 | 중도하차 처리된 수강생 |

> 미매칭 인원(HRD 없음 / 백오피스 없음)은 즉시 확인이 필요하므로 결과 테이블 최상단에 별도 표시됩니다.

---

## 결과 화면 구성

```
[요약 카드]  전체 인원 / OK / 주의 / 오류 / 미매칭 합계

[인원 현황 비교]  백오피스 vs HRD 구분별 인원 일치 여부

[필터 버튼]  전체 보기 / 주의·오류만

[내보내기]  CSV 내보내기 / 표 복사하기 / 슬랙 전달용 정리

[결과 테이블]
  번호 / 이름 / 주민번호 앞자리 / 백오피스 상태 / HRD 상태
  백오피스 출석률 / HRD 출석률 / 차이 / 판정 / 예상 사유 / 전달 체크
```

## 슬랙 전달 기능

1. 결과 테이블에서 전달할 항목의 **전달** 열 체크박스를 선택합니다.
2. `슬랙 전달용 정리!` 버튼을 클릭합니다.
3. 체크된 항목만 아래 형식으로 정리된 텍스트가 생성됩니다.
4. `복사` 버튼으로 클립보드에 복사 후 슬랙에 붙여넣습니다.

**출력 예시 (출석률 불일치)**
```
- 홍길동 : 6.0% 차이
  - 백오피스 : 92% / (46/50일)
  - hrd : 86% / (43/50일)
  - 차이 : -6.0%
  - 사유: 지각 처리 기준 차이로 추정
```

**출력 예시 (미매칭)**
```
- 김철수 : 백오피스에는 존재하나 hrd에 존재하지 않음
  - 등록 오류 확인 필요
```

## 주의 사항

- 백오피스 복사 시 **이름, 주민번호, 출석률(훈련기간)** 컬럼이 반드시 포함되어 있어야 합니다.
- HRD 엑셀의 첫 번째 시트가 출석부 데이터여야 합니다. 첫 행은 헤더(성명, 주민등록번호 등)로 인식됩니다.
- 이름에 포함된 영문자는 자동으로 제거 후 매칭합니다 (예: `홍길동A` → `홍길동`).
- 매칭 기준은 이름 + 주민번호 앞 6자리이므로, 동명이인이 있을 경우 주민번호를 반드시 확인하십시오.

## Vercel 배포 설정

사용자는 설정값을 입력하지 않습니다. Redash 연결 정보는 Vercel Serverless API에서 관리합니다.

1. `redash-queries.sql`의 두 쿼리를 Redash에 저장합니다.
2. 트랙·기수 목록 쿼리 ID는 `7982`, 출결 상세 쿼리 ID는 `7983`입니다.
3. Vercel 프로젝트의 Environment Variables에 아래 값을 등록합니다.
   - `REDASH_URL`: Redash 기본 주소
   - `REDASH_CATALOG_QUERY_ID`: `7982`
   - `REDASH_CATALOG_API_KEY`: 7982 쿼리의 Query API Key
   - `REDASH_DETAIL_QUERY_ID`: `7983`
   - `REDASH_DETAIL_API_KEY`: 7983 쿼리의 Query API Key
4. Vercel에 재배포하면 화면에서 트랙 목록을 자동으로 불러옵니다.

사용자는 화면에서 트랙과 기수만 선택하며, API 키와 쿼리 ID는 노출되지 않습니다.
